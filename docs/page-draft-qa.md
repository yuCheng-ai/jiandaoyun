# 页面新增字段和草稿恢复验收

2026-10-09。数据管理可以查看各页面已保存但尚未发布的新字段，区分主字段、明细和明细列，并直接进入来源页面定位控件。页面草稿可以恢复到最近发布版本；共享数据、记录和其他页面保持原样。

## 使用边界

- 管理员从应用的数据管理选择对象，在正式字段下方查看“页面待发布字段”。尚未保存的输入不进入此列表。
- 新字段保留各自稳定 ID；多个页面新增同名字段时提示检查复用，已经发布的同名字段和数据版本变化也会提示处理。列表不自动合并或发布字段。
- 页面恢复需要明确确认，会同时放弃服务端草稿和当前输入，恢复最近已发布页面的名称、布局、控件及数据版本。数据对象即使已经发布更新版本，也不会被回退。
- 恢复成功后重新建立编辑器状态，旧撤销历史不可重新插入被放弃字段。并发或服务错误保留当前输入。没有发布过的页面不提供恢复按钮。
- 页面归档已另见 page-lifecycle-qa.md；旧本地编辑器迁移与完整字段类型仍是后续工作，当前接口沿用文本、数字和单层明细支持范围。

## 自动化证据

backend/tests/page-drafts.test.ts 的 5 项真实 PostgreSQL 测试覆盖：

1. 汇总主字段、已有明细中的新列、新增明细及其子列；不返回配置默认值，不修改正式模型；保存取消与发布后列表消失。
2. 两页同名新字段保持不同身份；一页发布后另一页出现数据变化与复用提示，模型独立草稿继续提示处理。
3. 恢复页面保留共享模型草稿、业务值、其他页面草稿和发布历史，写入不可变审计；重启后结果一致。
4. 审计失败使整个恢复事务回滚；陈旧恢复请求不能放弃后续新草稿。
5. 管理员与工作空间隔离；无发布基线被拒绝。

## 初始数据草稿保留

2026-10-09 01:45 补充。修复数据对象首次发布后，仍绑定初始草稿的页面无法打开的问题。未发布的数据结构不具有不可变版本，因此现在由页面保存服务端初始模型及修订；其他页面或数据管理先发布时，原页面仍读取原基线及自己的待发布字段。页面编辑数据在同一事务、同一数据对象共享锁下读取，避免把不同时间的页面和模型拼在一起。

模型变化后允许继续保存页面草稿；发布会拒绝旧基线，明确指向“数据字段”检查和采用已发布模型。采用后保留布局、填写提示、稳定字段与明细列身份，其他新字段不会自动插入当前页面。数据对象还没有发布版本时不能把独立数据草稿当作已发布字段采用。初始页面即使只复用数据草稿中的字段、没有新增字段，也可在基线一致时原子创建首个数据版本和页面版本。

迁移 011-page-initial-model.sql 只回填尚未发布对象的已知结构，不推测已经丢失的历史基线；缺失时保留原草稿并明确报错。升级前检查本开发库没有初始页面，因此不存在这类旧异常数据。旧本地表单整体迁移不计为完成。

backend/tests/page-baselines.test.ts 的 6 项真实数据库测试验证：数据管理先发布后重新读取及服务重启、旧基线继续保存与显式采用、另一初始页面先发布、约束与明细归属不随独立草稿修改或归档恢复漂移、无新增字段的首次发布及写入故障回滚、迁移保留已知结构且不伪造历史。请求中伪造初始模型与修订不能覆盖服务端基线。frontend/tests/page-designer.test.ts 新增 2 项验证采用首个发布模型时保留明细列与布局，以及拒绝采用未发布模型。
