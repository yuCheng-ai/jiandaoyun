# 局部编辑暂存与恢复验收

2026-10-08。已接入个人信息、数据推送、插件、智能助手、提醒、自定义按钮配置和正式 `FormRuntime` 填写/编辑；其他独立配置弹窗尚未接入，不将统一基础设施视作全覆盖。日常恢复使用自动暂存与原编辑器内确认；旧填写缓存迁移、只读字段保护以及上下文属性顺序兼容的最新实现见 [填写草稿验收](filling-drafts-qa.md)。

## 实现边界

- `domain/editorDrafts.ts` 定义独立恢复文件与 JSON 检查；`editorDraftAdapters.ts` 负责个人信息、推送配置、字段值的恢复解析。
- `useEditorDraft` 登记活跃编辑器，把脏输入保留在 Pinia 内存。来源路径和初始配置快照在编辑开始时固定，不随导航或外部更新重新标记。
- 个人信息、推送配置在输入停止 350ms 后自动写入 `sessionStorage`；表单填写遵循 `cacheDraft` 配置。刷新和卸载前尝试保留最后输入，失败时保护退出。与业务 Repository、保存事务和发布版本分离。
- 恢复要求编辑器打开、稳定来源键及上下文相同，再次确认替换当前输入。确认期间编辑内容变化则拒绝执行。恢复只改输入，不调用提交、发布、支付、消息或网络操作。
- 个人信息只恢复姓名、邮箱、电话；推送只带凭证引用；填写保留只读/遮蔽字段当前值，按字段 ID 和子表作用域检查值结构，正式保存继续经过原业务校验。
- 保存成功、显式放弃清理本次编辑快照；此前导入/保留的其他快照继续存在，可单独移除。没有自动合并不同版本的配置或记录。
- 最多 50 份，单份值 1 MB，独立文件和总内存集合 15 MB，标签页暂存 3 MB，均按 UTF-8 字节计数。存储配额或权限错误保留内存输入，不覆盖损坏的原暂存。
- 工作空间恢复副本增加 `editorDrafts`；独立暂存或完整恢复文件均可通过文件或 JSON 文本导入。全量工作副本仍包含已有本地工作空间内容，独立暂存不包含工作空间密钥仓库。

## 自动暂存与就地恢复更新（2026-10-08）

按客户菜单减负方向，日常编辑不再打开工作空间恢复工具。当前会话的输入不会触发恢复横幅；重新打开同一编辑器时，才显示上次未保存的内容。可就地确认恢复或暂不恢复。多份历史内容提供时间选择；结构、原数据或成员变化时禁止直接应用。恢复沿用原草稿 ID，保存或明确放弃后清理，正常输入仍不触发业务操作。

自动保留与错误按编辑来源处理；一处编辑成功不会掩盖另一处失败。损坏的原文件不能被覆盖。表单设计设置的“表单前台缓存”改成“自动暂存填写内容”，保留原布尔语义。记录管理与成员弹窗的明确放弃调用运行时清理方法，避免卸载时又留下恢复副本。未开启自动暂存时仅保留当前页面内存输入，刷新仍受退出保护；本轮没有把关闭状态改为启用。

实际浏览器验证：

1. 个人信息输入测试姓名，当前没有恢复横幅；直接刷新后，原成员仍为张三。打开个人信息、确认恢复才显示测试姓名，恢复后焦点落到姓名输入框。选择放弃并再次刷新，恢复提示不再出现。
2. 推送配置输入测试名称，勾选修改事件后直接刷新；新建推送显示上一份内容，确认恢复后名称和两个事件均回显。没有保存配置或执行推送；放弃后重开无恢复提示，配置数量仍为 0。
3. 390×844 发现恢复提示导致弹窗外层也滚动，随后将带恢复入口的弹窗改为固定头尾、正文独立滚动。复验“下一步”底部为 798px，小于视口 844px；页面宽度与滚动宽度均为 390。恢复按钮可用，焦点回到推送名称；完成后重置视口。
4. 数据管理中修改既有记录，明确放弃后重开仍显示原值，没有恢复提示。测试期间没有提交、发布或改动通讯录；工作台仍为 18 表单、25 条记录、8 待处理。
5. 开发中的旧 Pinia 实例曾在热更新后缺少新增方法，刷新后恢复；05:39 UTC 之后复验没有新的 error/warn。未把这次开发态错误记为零错误记录。

新增 7 项测试覆盖防抖最终值、当前会话排除、恢复后清理、放弃取消延迟写入、配额失败与重试、成员切换、损坏副本，以及关闭自动保留设置。全量 251 项测试通过；最终类型检查、生产构建和 4 项 Sites 检查通过。截图：[原编辑器内恢复](editor-recovery-inline.png)、[手机恢复及固定底栏](editor-recovery-inline-mobile.png)。

## 插件与智能助手恢复更新（2026-10-08）
