## 工程边界

- frontend/src 保留 Vue 3、Pinia、领域层、Repository 和懒加载页面。既有本地工作台继续可用，逐项迁移接口；服务端协作入口准确标识支持范围。
- backend/src 使用 NestJS 模块和 PostgreSQL，参数验证、授权与数据变更均在服务端执行；不信任浏览器传入的成员身份。
- packages/contracts 是共享 Schema 和接口类型的来源。类型共享不替代服务端运行时校验。
- .openai/hosting.json、worker/index.js、scripts/prepare-sites-build.mjs、tests/sites-worker.test.mjs 保持原内容。前端构建仍输出根 dist/client，Sites 静态 worker 不承担 NestJS 后端执行。
- 开发 PostgreSQL 使用独立 Compose 项目和 55432 端口，避免接触机器上已有数据库。测试使用独立 schema，不清空开发数据。
- 本地账号凭据由 setup:local 随机生成并保存在被忽略的 .env；不接入企业 SSO，不把浏览器体验成员切换当真实账号认证。

## M1 数据与安全契约

表单发布版本只追加，记录固定引用发布版本。当前授权独立于历史业务值，成员权限变更立即影响读取与修改。

明细行使用服务器分配的稳定 ID；更新命令明确指定记录、明细行和字段。各字段维护修改版本，在数据库事务和行锁下核对。不同字段可以基于较旧的整体快照安全修改，相同字段修改冲突返回 409，前端保留输入。

记录新增/修改和流程发起具有幂等键，同一请求重试不重复创建记录或任务；定义发布通过 revision 拒绝重复旧命令。数据校验、授权、写入和审计处于明确事务边界。权限过滤同时覆盖数据和字段修改版本，错误及日志不回显隐藏字段内容。

首版只开放服务器已实现完整校验的字段和规则，未支持的配置在发布时列明并拒绝，不把客户端校验视为服务端支持。附件、外部 HTTP、支付、通知和 ERP 等仍不计为真实接通。
