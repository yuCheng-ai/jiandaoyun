# 通用交互与保存机制巡检

2026-10-09。检查工作台、原应用/表单入口、设计/发布/填写/数据管理、组织/权限、扩展/支付，以及服务端数据/页面/关系/任务/迁移入口的公共状态与保存边界。

## 本轮结论

新建与编辑被无关更新拦住的根因是整工作区快照检查；提示文字只是其表现。原来的“仅允许新增独立表单”例外已删除，改为统一的操作对象检查。公共弹窗的工作区告警接口、全局保存忙状态和不能执行的委托入口也已删除。

这次整改完成的是下表中的通用机制。完整平台交付仍按 frontend-closure.md 和 development-plan.md 验收，不能把测试全绿等同于所有业务功能实现。

## 检查与整改矩阵

| 检查范围 | 确认的问题 | 公共处理与验证 |
| --- | --- | --- |
| 新建应用/表单/分组 | 另一张表单改名、记录或组织变化会阻止创建 | 在共享锁内读取最新资源后执行创建；重新检查目标应用、分组和数量；并发独立创建都成功 |
| 表单/流程设计及扩展保存 | 全局快照版本把不同表单耦合；放行例外难以扩展 | 所有公共本地写命令必须声明操作对象；设计草稿各自保存打开时的基线；不同表单可提交，同表更新保护双方修改 |
| 已打开的设计草稿 | 其他成功操作刷新数据后，旧草稿可能被当成最新稿 | 原始设计基线独立于已保存工作区；新建、配置保存或改名不能解除旧设计冲突 |
| 填写/记录修改/审批/支付 | 不同记录互相阻塞，直接放行又可能漏掉最新约束 | 检查当前记录/订单，在最新数据上重新运行唯一、收集上限、权限、组织、关联、支付与自动化校验；未发布的设计变化不阻止填写已发布版本 |
| 记录、商户、访问设置编辑 | 其他操作刷新了已保存数据后，旧输入可能覆盖新内容 | 保留编辑开始时的记录值/商户/访问配置，提交时再次检查；输入保留，失败不报告成功 |
| 成员/部门/角色/分组 | 组织编辑上下文包含全应用和表单清单；其他成员修改也会导致失效 | 上下文限于当前对象、选中成员和角色归属；保存后再检查目标角色、应用与表单引用 |
| 共享弹窗与选择器 | 无关本地保存能让服务端弹窗也进入忙状态；每个弹窗都依赖工作区告警 | 删除 BaseDialog 的工作区依赖和告警插槽；保存状态由当前操作显式传入，保留取消、Escape、焦点和未保存保护 |
| 页面对焦/跨页通知 | 仅检测到外部变化就被当作保存失败 | 检测只返回状态，不弹错误；进入新页面/新编辑器时只读更新已保存资源；真正写失败才显示提示 |
| 保存错误显示 | 一次失败跟到新建和其他业务页面 | 提示绑定失败发生的路由；冲突命名当前表单、记录、权限或订单；独立写成功不会解锁旧草稿的原始基线 |
| 共享写锁 | 短暂的另页保存让用户立即重试 | 自动排队，获得锁后重新读取与检查；5 秒超时保留输入，缺少安全锁不使用会覆盖数据的降级写入 |
| 只读迁移报告 | 最新报告的“查看设计”被旧工作区状态阻止 | 根据已检查的最新资源导航；旧编辑器需保留时在新页打开；报告自身过期仍需重检 |
| 流程保存失败 | 所有失败都被描述成存储不可用，并要求导出 JSON | 显示本次失败原因和保留状态；删除把技术备份作为默认处理的硬编码 |
| 工作台待办委托 | 界面报告配置保存成功，运行时完全不读取该配置 | 删除入口、选择器和无效保存代码；实际委托执行继续保留为未完成功能 |
| 存储兼容读取 | 初次打开和另存设计可能清洗或截断未知资源后继续写入 | 仓储统一检查原业务值是否完整保留；允许补默认属性，禁止丢字段、记录、数组元素；原数据无法完整读取时不给写基线 |
| 服务端页面/记录/权限/关系/流程 | 检查是否误用整个工作区版本或本地错误状态 | 服务端使用对应资源的修订号和事务；相关页面显式传递自身 busy，已移除本地弹窗耦合；未修改服务端接口，运行现有完整后端回归 |

## 保存契约

1. `workspaceTransactions.ts` 描述每个命令的操作对象。新增命令缺少声明会在类型检查中失败；直接写整快照仍保留严格保护。
2. 仓储与共享锁仍负责原子比较和提交。获得锁后读取完整最新快照，对当前操作对象比较基线，再运行现有业务校验和同步提交。
3. 新读取的资源不会替换正在编辑的设计对象、撤销历史和表单输入。无关对象采用最新已保存内容；相同对象发生变化时保存失败，现有回滚和失败尝试保留机制继续生效。
4. 编辑器的原始基线只在该编辑成功保存后更新。读刷新或其他对象的成功保存不能提升它的版本。
5. 未知内容、清除、读取异常或检查期间再次变化均不授权旧快照覆盖。技术恢复工具仍是失败场景下的次级工具。

## 后续验收与界限

- 当前是按表单、记录、配置和组织对象保护；同一表单不同字段的自动合并尚未实现。服务端同一整体组织配置的并发编辑仍采用修订号保护，不自动合并。
- 待办委托缺少实际任务转交、权限检查和运行记录，不能再通过一个本地设置伪装完成；它仍是功能义务。
- 旧本地入口迁移、其余字段及完整流程、F1–F10 最终综合验收仍按既有计划推进。已经提供的其他业务能力没有从验收范围删去。
- 开发热更新会保留旧页面的存储实例。新版保存机制在新打开的预览生效；旧页不强制刷新，以免丢失未保存输入。这不是生产发布的多页版本升级方案。
