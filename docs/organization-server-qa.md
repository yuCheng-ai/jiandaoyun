## 已接通的业务路径

管理员从应用管理或协作空间的“组织与成员”维护部门层级、真实登录成员的主部门与兼职部门、角色组，以及指定成员和部门组成的业务角色。组织配置使用服务端版本保存，有未保存决定、并发冲突和明确放弃后重新读取；不改变成员的平台管理员身份。

数据对象的“数据权限”可以授权给指定成员、部门或角色。部门可选择是否包含下级，角色成员按当前配置解析。字段和明细列、关联操作仍使用稳定 ID。数据管理、页面、记录、关联候选和任务处理均按同一服务端规则检查。

流程模板可选择指定成员、部门成员逐人办理或角色成员逐人办理。预览列出每位成员的任务；按明细任务再按当前行展开。前置依赖等待该节点展开的全部成员和明细任务。角色为空或任何处理人无权办理时明确报错，不默默跳过。最多展开 300 项任务。

## 权限规则

| 情况 | 实际行为 |
| --- | --- |
| 多个来源授权 | 有效授权叠加；某一来源“不授予”不代表撤销其他来源 |
| 本人记录可编辑 + 全部记录只读 | 先按当前记录创建人筛选授权，其他人的记录仍只读 |
| 明细父级只读、子列可编辑 | 在每项授权内部先限制父子权限，再合并；不能从两项授权拼出额外子列写权 |
| 新增与修改分别授权 | 新增所需的字段写权不能借用另一项仅允许修改的授权 |
| 所属部门记录范围 | 按处理人全部当前部门及其下级部门，匹配记录创建人的当前归属；包含兼职部门 |
| 成员调动 | 下一次请求立即按新组织配置计算，历史记录的可见范围也随当前归属变化 |
| 已发出的任务 | 保留原处理人；调动造成失权时阻断办理，恢复授权后原任务可以继续 |
| 发布新字段 | 已授权普通成员人数包含部门/角色成员并去重；新增字段仍需另行授权 |

部门范围目前依据记录创建人，不是独立的记录归属部门。管理员始终可管理本工作空间记录。页面及任务范围只能收紧实际权限；任务分配不额外赋予数据权限。
