# 历史身份与记录归属验收

2026-10-09 05:06，北京时间。已将记录创建者与可登录账号分开：记录可以引用已确认的独立历史成员，主表和明细中的历史成员、部门可以显示原名称。历史身份不能登录，不进入当前组织、授权或待办选择。完整旧应用导入尚未执行。

## 实现与约束

- 身份对应草稿仍只预留标识；确认时，在同一事务中保存明确选择为“历史身份”的独立档案和审计。先重新核对来源、组织及跨应用对应，失败整笔回滚。撤销确认保留已存档的身份，不创建账号或产生有效业务授权。
- 新增 `historical_identities` 保存来源、类别、原名称及首次确认批次；档案不可覆盖。同一来源在多个应用中使用相同身份，后续名称变化不改写首次保留的历史名称；各批次原始来源仍独立保留。
- 新增 `record_principals`，只允许账号成员或历史成员作为记录创建者。已有记录的创建者 ID 保持不变；记录的工作空间与创建者工作空间通过外键共同检查。部门和角色不能被当作创建者。
- 账号表仍独立承担登录、会话、授权对象及任务办理人职责。新增账号自动注册记录创建者身份，但独立历史成员不写入账号表。部门/角色档案也不写入当前组织配置。
- 记录详情及任务详情显示创建人；主表、明细、关联记录的身份名称通过共用解析返回。独立历史身份显示“历史身份”，停用账号仍显示“已停用”。
- 历史名称只按当前可读字段、页面与任务行的结果解析；不提供可浏览全部历史档案的普通成员接口，跨工作空间或类型不一致的标识不返回档案名称。
- 保留未改变的历史值，允许当前成员补充其他有权修改的内容。当前选择器不提供历史档案，新记录、追加明细、授权、当前组织成员及任务分配不能指定历史身份。
- 修改轨迹中的操作人仍为实际登录成员。修改记录不会把历史创建者替换为操作者；“本人”或“部门”范围也不会因此把历史记录归到导入管理员名下。原创建部门及其迁移后权限语义仍需后续完整转换，当前范围继续依据服务端组织规则。

数据库升级 014 保留已有创建者引用，并回填升级之前已确认的历史身份资料；迁移校验账本、旧 M1 数据升级和重复启动继续通过。
