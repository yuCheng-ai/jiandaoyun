# 配置编辑恢复验收（2026-10-08）

本轮补齐打印模板、在线支付配置、演示商户和快捷填报四类编辑器。恢复仍需使用者确认，不自动提交或修改已发布版本。

## 实现

- 复用 `useDraftDismiss` / `useEditorDraft` / `EditorDraftNotice`，按配置稳定 ID（或新建入口）区分编辑内容；上下文包含原配置、相关表单结构及当前成员。上下文变化时不直接恢复。
- 保存等待有可见状态，拒绝重复保存；保存返回失败或抛错均保留输入并给出重试提示，成功回执后才清理暂存。明确放弃也清理对应暂存。
- 暂存适配器检查输入结构与对象身份，不要求编辑内容已满足全部业务校验。支付有效期清空仍保持空值；快捷填报保留别名输入中的尾部逗号和空格。预览结果不作为已验证结果恢复。
- 修复公共初始化顺序：会话 ID 在渲染后捕获输入之前建立。此前先更新配置再打开窗口，可能留下默认值的孤立暂存，表现为放弃后又提示恢复。新增测试先复现，再验证修复。

## 自动化证据

`configuration-recovery.test.ts` 的 15 项测试使用真实 Vue 编辑器、公共弹框、Pinia 暂存仓库和 sessionStorage；只替换保存边界与无关的预览组件。覆盖四类编辑器重建后恢复、保存拒绝/抛错、重试成功后清理、连续点击保存、取消/继续/放弃，以及当前成员变化后的恢复隔离。适配器测试验证稳定字段绑定、模板顺序、未完成数值、别名原文和无效结构拒绝。

全量 27 个测试文件、309 项测试通过。`npm run build`（含 TypeScript）及 4 项 `npm run test:sites` 通过，Sites 所需三个输出文件存在。保留已有 PDF 懒加载块大小警告，没有调整阈值隐藏警告。

## 浏览器证据

在独立本地标签页，对“异步保存 · 验收示例”进行正常 UI 操作，全部测试输入最后明确放弃，没有保存演示商户、支付配置或模板。

1. 在线支付填写订单说明并清空有效期，再打开商户子窗口填写名称和备注。刷新后父、子编辑器分别出现恢复提示；确认后各自输入均恢复。放弃商户修改后，父窗口订单说明和空有效期仍保留。[嵌套恢复截图](configuration-recovery-nested.png)
2. 打印模板填写名称和页尾，改为 A5；刷新、重开并确认恢复后，三项输入及实时预览一致。
3. 快捷填报选择单行文本，填写别名 `服务名称，项目名， `、字段说明和示例；刷新并确认恢复后全部保留，尾部标点和空格未被丢弃。[恢复后截图](configuration-recovery-quick-fill.png)
4. 390×844 下页面宽度与滚动宽度均为 390，关闭、取消和保存可达；取消并放弃后重开没有旧恢复提示。[窄屏截图](configuration-recovery-mobile.png)
5. 浏览器 error/warn 为空，验收结束恢复原视口。

## 剩余范围

本轮不代表所有编辑器恢复完成。权限组与发布设置两阶段恢复已在后续验收补齐，详见 [权限恢复验收](access-recovery-qa.md)。组织编辑、其他内嵌扩展设置和受限成员恢复路径继续按 [闭环范围](frontend-closure.md) 检查。跨版本自动合并仍未实现。异常保存路径由组件测试验证，没有在用户浏览器故意破坏持久化。
