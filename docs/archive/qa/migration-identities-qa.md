## 已实现范围

- 从最新已保存的原工作空间构建来源清单，包括盘点中直接引用的身份，以及相关部门层级、负责人、部门成员和角色引用。相同名称不产生自动对应。
- 仅上传应用名称、来源身份标识、名称、状态、资源数量与来源摘要。业务值、组织联系方式、登录凭据及原配置内容不进入批次元数据。
- 来源摘要基于原始持久化工作空间计算，排除最近访问导航缓存；兼容读取会遗漏资源时停止。当前校验范围保守地覆盖整个工作空间，其他应用或组织修改也可能要求更新来源。
- 来源命名空间独立保存，不修改原业务存储键。浏览器支持 Web Locks 时串行分配，多个本地应用共用同一命名空间。同一来源身份的历史标识由服务端稳定预留，不实际创建账号、部门或角色。
- 身份决定支持尚未决定、关联现有同类身份、保留历史身份。停用目标可用于历史对应，但检查明确提示不能用于有效授权或新任务。原目录缺失的引用保持可见。
- 草稿保存使用版本检查；重复请求重试去重，保存失败保留输入。更新来源保留相同身份的已保存决定，新增身份回到未决定状态，移除项仍保留在不可变审计快照中。
- 确认前检查目标所属组织与类别、同批次不同来源身份的目标冲突、其他已确认应用的同源一致性。确认事务重新验证组织和检查标识，跨应用同时确认也不能绕过冲突检查。
- 已确认批次需要撤销确认后修改。可以查看同一来源的其他应用，并明确撤销相关身份确认以解决冲突；对应草稿保留。操作历史随数据修改原子记录。
