# 共享写入锁验收（2026-10-08）

## 实现与边界

- 工作空间的公共持久化动作统一申请同源 Web Lock；仓库拒绝未持锁的直接写入。
- 获得锁以后，业务变更、旧快照检查、写入和失败回滚保持同步。内部发布、提交、支付、自动化调用不重复申请锁。
- 同页重复点击不重复执行；其他页面持锁时立即返回未执行。重试仍检查旧快照，不把旧页面当作最新数据。
- 参数在等待授予锁前复制，保留 Date 类型；最近访问与一次性预填仍独立，不触发业务快照写入。
- 未提供 Web Locks 或请求遭拒时停止写入并提示，保留编辑输入，没有无锁降级路径。
- 页面等待保存结果后才关闭、跳转或显示成功；填写失败采用错误样式，冲突提示独立占位，不再覆盖底部按钮。

锁只协调同源、同协议的当前版本页面。旧版本前端、直接改动存储、清理浏览器以及跨设备操作不受此保证。当前仍不自动合并草稿，不把失败记录或支付操作重放为成功。

## 自动检查

7 项新增测试：绕锁写入禁止及异常释放、同时写入只接受一个及旧页重试、授锁前不修改数据及输入快照、重复点击、容量失败回滚与重试、不支持/拒绝锁、恢复共用锁、嵌套动作仅申请一次。既有所有存储测试已改为等待真实的异步结果，保留原有历史版本、权限、支付与自动化回滚断言。

合计 229 项业务测试、TypeScript、生产构建、4 项 Sites 检查通过。构建保留 `dist/client/index.html`、`dist/server/index.js` 和 `dist/.openai/hosting.json`。
