# 页面归档与恢复验收

2026-10-09。应用管理可以归档和恢复表单页面。归档保留页面草稿、待发布字段、发布版本及业务记录，停止普通页面入口和新流程使用；已经发出的任务继续按原页面版本及当前权限处理。

## 行为边界

- 管理员在“表单页面”查看使用中或已归档页面。归档、恢复均先检查当前页面修订、流程草稿、全部已发布流程版本和已有任务，再明确确认。
- 已归档页面可查看草稿及预览，不能修改、发布或放弃草稿；待发布字段清单仍显示来源及归档状态。恢复沿用同一页面身份、草稿和版本，不重新发布或自动采用最新数据模型。
- 归档期间普通页面读写、记录升级和关系增删被服务端拒绝。新增流程草稿不能绑定归档页面；已有草稿可以保留原引用供调整，但不能发布或发起。已发任务可读取和写入获授权字段、完成任务；任务分配不授予数据权限。
- 已归档页面不再阻止模型移除字段，旧版本保持可读。恢复预览说明当前模型与页面原数据版本的差异；恢复后页面仍按旧契约使用，重新成为有效依赖。
- 归档、恢复、审计在同一事务完成；过期预览、陈旧修订及审计失败不会留下部分结果。新流程发起、关系写入与归档通过对象锁串行化，在写入事务中重新检查页面状态。
- 旧定义发布兼容入口不会改写或重建已归档的受管理默认页面。

## 浏览器整链

在“字段与页面验收”应用，用“字段变更处理页”页面 V1 / 数据 V1 创建“页面归档协作验收”记录，数量 1。配置并发布“页面归档验收”流程，发出一项“归档后办理”任务。

1. 归档预览显示草稿、已发布流程引用及 1 个未完成任务。确认后普通列表收起该页面，已归档列表可查看只读草稿。
2. 新流程任务预览被拒绝，确认发起不可用；错误说明页面已归档和已发任务的继续处理路径。
3. 从原流程进入任务，按原页面 V1 将数量保存为 2，然后完成任务。流程显示 1/1 已完成，轨迹包含数据保存与任务完成。
4. 恢复预览显示 0 个未完成、1 个已完成任务，并明确业务名称、数量、明细数量已在当前模型调整；恢复仍使用数据 V1。
5. 390×844 下恢复对话框完整显示，页面宽度为 390，按钮可达。确认恢复后，正常页面可再次打开该记录，数量仍为 2；流程重新预览成功，随后取消，未创建多余实例。
6. 浏览器警告和错误为空，验证后恢复默认视口。已有“历史规则验证记录”和“验收处理页”的待发布字段草稿未修改。
