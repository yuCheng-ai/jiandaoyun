2026-10-09 05:45，北京时间。本轮补齐历史记录的导入事务组件、不可变来源档案，以及按记录创建部门计算的权限范围。完整应用导入和原流程切换仍未开放；当前浏览器样例的应用、数据结构是受控验收准备，记录通过生产代码中的事务组件转换。

## 原记录保留规则

`record_origins` 将原状态、原创建／修改／删除时间、原创建者和部门名称、处理轨迹保留在独立档案中，关联不可变资源快照及预留记录身份。数据库拒绝更新、删除来源档案，拒绝跨来源／工作空间的对应。原历史没有实际操作人字段，不能把每条原轨迹伪造为当前导入人的动作。

内部 `RecordOriginService.importIn` 在调用者事务中核对最新快照、已确认身份、组织检查依据，以及已导入的数据结构、应用和原发布版本。记录值、稳定明细身份、原创建者、创建部门、时间、来源档案及导入审计同事务写入。审计失败回滚；并发和重复导入不产生副本，不覆盖后续编辑。该组件没有公开的部分导入接口，未来完整应用迁移必须先转换并核对其他资源，再统一调用。

| 原记录情况 | 当前存储与运行规则 |
| --- | --- |
| 草稿 | 保存为原版本的记录草稿，不填入当前默认值，不进入关联与流程 |
| 已提交／已通过／已退回 | 业务记录可按当前授权读取；三个原状态在档案中分别保留，不伪造新流程运行结果 |
| 原已删除记录 | 原删除时间写入归档状态，不进入正常列表；管理员可按明确记录身份读取来源档案 |
| 缺少原修改时间 | 档案仍表示未留存；运行记录用原创建时间初始化修改时间 |
| 缺少原创建部门 | 保留未知，不从创建人当前部门或导入人部门推断 |
| 原当前节点 | 仅保留原节点引用，不能据此自动生成新待办；原流程的完整转换仍是导入门槛 |

轨迹检查逐项验证标签、动作和时间，保持原有顺序及时间字符串。格式不合法时原始快照保留，但该记录不进入可转换结果；错误消息不回显轨迹业务文本。

原轨迹是没有字段／明细权限信息的自由文本，因此仅管理员可通过独立接口和窗口读取。普通成员及任务详情不返回轨迹或来源入口；当前数据操作继续经过记录、页面、字段和明细范围检查。

## 创建部门与权限

原本地系统的部门范围按记录创建时留存的部门直接匹配，服务端既有范围按创建人当前归属（含下级）计算。迁移不能悄悄把两种规则混为一种。

- 新增 `created_department_ids`；新记录和草稿从当前认证人员的服务端组织快照捕获，忽略客户端覆盖，后续提交、修改或人员调动不更新它。此前未留存的数据保持 `null`，不猜测补填。
- 授权增加明确的“部门范围依据”：默认“创建人现在所在的部门”保持既有行为；“记录创建时所属的部门”与查看人当前所属部门直接匹配，包含兼职部门，不自动纳入下级部门，保持原系统的这一范围含义。
- 列表 SQL、详情、修改、关联候选和直接关联都使用相同依据。混合授权仍先按记录范围和操作／父子列限制计算，再合并字段权限。
- 缺失、空数组和已明确映射到独立历史部门的情况分别保留。独立历史部门不成为当前组织成员关系；不会自动扩大授权。原权限组的完整转换仍待接入。
