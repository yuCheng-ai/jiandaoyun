# 自定义按钮验收（2026-10-08）

## 实现

- 三步配置：显示位置与条件 → 动作和字段映射 → 样例检查与保存；具备启停、复制、归档恢复、搜索和未保存关闭保护。
- 填写页、数据详情、列表行共享 `CustomButtonBar`。填写页按当前发布版本显示；记录按其提交版本显示，旧记录不混用新配置。
- 动作包括更新字段、带值打开已发布表单、带参数打开 HTTP(S) 链接。固定值使用目标字段控件，来源字段保存稳定 ID；文本输出显示人员/选项名称，数字保留 0，跨表单选择项按 ID 或唯一标签对应。
- 更新先展示差异；填写页只回填，记录更新复用 `updateEntry` 的格式、唯一性和动态范围校验，保留流程位置，追加按钮名称和数据更新事件。存储失败整体回滚。
- 跨表单仅打开填写页，不自动提交。预填数据存于 Pinia 闭包中的临时队列，URL 只有一次性标记；绑定目标表单与发布版本，失效时明确提示。
- 链接参数自动编码。拒绝非 HTTP(S)、相对地址和含账号密码的 URL，先展示完整链接再确认打开；配置试运行不访问目标地址。
- 只写入可编辑的普通值字段，支持文字、数字、日期、选择、人员和部门等；不对附件、子表行、关联结构和计算字段直接赋值。配置与运行阶段检查失效字段、重复目标、隐藏/只读字段、选择范围和单选基数。

完整业务套件 115 项通过；TypeScript、生产构建以及 4 项 Sites 测试通过。构建仍输出要求的 client/server/hosting 文件。

## 浏览器

桌面以「合同提醒 · 验收示例」建立并发布两个按钮到 V2：

1. 「标记待续签」在填写页回填名称，未自动生成记录；随后手动提交「按钮验收原记录」。
2. 列表的 V2 记录出现自定义按钮；原有 V1 记录保持无按钮。
3. 列表执行更新，详情显示新名称和 `按钮「标记待续签」· 修改记录` 历史。
4. 详情执行「复制为续签申请」，确认后打开另一张「项目申请示例」V1，项目名称已带入，预算默认值保留，仍显示提交按钮。
5. 保存刷新后按钮列表和字段映射保持。验收发现并修复了列表调用 `entrySchema` 的参数错误；修复后的操作没有新增控制台错误或警告。

窄屏使用同源验收框架实测 390×844（clientWidth=scrollWidth=390）：

1. 配置「打开相关工作台」，绑定合同名称到 `contract` 链接参数。
2. 检查面板展示编码地址，取消触发未保存保护，可继续编辑并保存。
3. 发布后填写 `链接验收 A&B`，运行确认显示 `A%26B`，确认后新标签页打开本地工作台并携带正确参数。没有发送到外部系统。

## 边界

这是本地前端业务闭环，不是服务端授权。真实多用户权限仍需后端。临时预填上下文只在当前页面会话有效，不承诺刷新或跨设备恢复；表单本身已开启的填写缓存仍按原配置工作。外部站点的实际响应、目标系统业务处理不在本次验证内。
