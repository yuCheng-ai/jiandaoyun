# 记录草稿与提交验收

2026-10-09 05:26，北京时间。新服务端记录支持先保存未填写完整的草稿，随后继续填写并正式提交。此能力与设计表单时保存的页面草稿、数据模型草稿相互独立。旧应用的原审批状态、历史轨迹、创建部门及正式资源导入仍未完成。

## 实现与约束

- migration 015 增加记录 `draft / active` 状态，现有服务端记录保持正式状态；归档仍由独立的 `archived_at` 表示。本次没有把旧系统的批准、驳回状态合并成正式记录。
- 草稿允许暂缺模型和页面的必填值，仍检查已有值的类型、范围、组织身份与修改权限。绑定原发布数据版本，页面版本必须明确；保存草稿不发布数据模型或表单页面。
- 草稿由创建者或管理员查看，具有全体记录读取权限的其他成员也不能读取。创建者根据当前新增权限继续编辑自己的草稿；只有新增权限不意味着可修改已提交记录。权限被撤回后不能继续写入或提交。
- 正式提交校验整个记录版本、当前权限、原数据版本的必填规则及本次页面的补全要求。待保存字段、明细动作、状态变更、幂等命令和审计在同一事务中提交；校验或审计失败全部回滚，客户端保留输入。
- 提交保留记录 ID、明细行 ID、原创建者和创建时间，审计记实际操作人。相同请求重试不重复提交；重复读取按当前权限返回。
- 草稿不进入关联候选、直接关系绑定、流程记录候选、直接流程任务或跨记录等待。提交后才能用于业务协作。草稿不提供记录版本升级，需先按原版本补齐提交。
- 应用页面和协作空间的记录列表增加“正式记录／草稿”范围。新增记录可保存草稿或直接提交，草稿可继续保存或正式提交。保存成功切到对应列表，提交成功切回正式记录。

## 浏览器与数据库证据

在“字段与页面验收”应用中新增合成页面“草稿提交验收”，经 API 建立发布的测试结构；记录的创建、保存、编辑和提交均通过真实浏览器完成。没有替换已有页面或导入旧 OA 数据。

1. 新增记录不填事项名称、数量及必填明细，保存为草稿成功，列表切到草稿。
2. 刷新后重新选择草稿列表，可以打开原草稿。
3. 只填写名称时正式提交失败，提示数量必填，保留名称输入。补充空明细后保存草稿成功。
4. 切到 390 × 844 窄屏，两个对话框宽 358 像素，内容宽与可用宽均 356 像素，无对话框横向溢出。
5. 在窄屏填写数量 3 和“补齐的明细”后提交，列表自动切到正式记录。再次打开值正确，按钮为“保存修改”，不再出现草稿提示。
6. 数据库核对记录从 revision 2 / draft 到 revision 4 / active；此次字段编辑与正式提交各记一次审计。记录、原创建者、明细行身份不变，只有一次 `submit-draft`。旧 OA 身份批次仍 revision 2 / draft，19 项对应未决定。
