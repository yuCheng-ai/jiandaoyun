## 配置入口

2026-10-09 仅添加补充：应用页面已按真实服务端权限提供新增、本人的记录草稿和原子提交，提交后无查看权限仍确认保存；已有记录的筛选及组字段不能借给新增。新字段的页面草稿和发布机制不变。原开始节点和收集规则仍是完整迁移条件，见 registration-access-qa.md。

应用管理中设置数据管理、表单页面和流程三个入口。它们管理应用资源，不作为某一张表单编辑器中的三个步骤。普通成员从业务页面和待办使用应用，不需要进入数据管理。

| 入口 | 管理内容 | 与其他资源的关系 |
| --- | --- | --- |
| 数据管理 | 客户、订单等数据对象，字段、明细、关系、约束及使用情况 | 一份数据可供多个页面和流程使用 |
| 表单页面 | 控件、布局、显示名称、说明、交互与数据绑定 | 默认绑定一个主对象，可通过明确关系展示其他对象 |
| 流程 | 任务、参与者、记录和明细范围、依赖、等待及处理页面 | 节点绑定业务记录与页面，流程不依附于唯一表单 |

在页面编辑器中可以看到当前数据对象，进入其字段设置或查看使用情况。这是上下文入口，不另建一套数据配置。简单的单表流程仍可以从表单快捷创建，底层流程保持独立身份。

数据管理首版采用对象列表、字段列表和关系配置。关系图作为后续辅助工具，不要求用户先操作数据库图才能建立表单。

## 新建和拖拽

新建表单页面有两条路径：默认创建新的业务数据，也可以选择已有数据对象。

选择新数据时，系统在同一草稿中建立数据对象与默认页面。拖入文本、数字等新字段，同时创建数据字段和绑定它的页面控件；命名、排序和排版仍在熟悉的画布中完成。保存失败不得留下只有数据字段或只有控件的半成品。

数据管理和表单编辑器共用字段定义。表单中的“新建字段”提供就地创建入口，“已有字段”提供复用入口；用户不需要每增加一个输入项就离开表单去建模。以在检验页面拖入“检验结论”为例：

| 操作 | 数据字段 | 当前页面 | 其他页面 |
| --- | --- | --- | --- |
| 拖入新字段 | 产生待发布字段 | 出现绑定该字段的控件 | 保持原样 |
| 保存草稿 | 随页面草稿保存，正式模型不变 | 保留编辑状态 | 保持原样 |
| 发布 | 将字段加入所属数据对象 | 控件与字段一起生效 | 可采用新版字段后自行选择复用 |
| 拖入已有字段 | 复用原字段身份 | 增加填写或展示入口 | 仍使用同一业务值 |
| 移除已发布字段的控件 | 字段及已有值保留 | 移除当前展示入口 | 保持原样 |

拖入明细中的新字段成为对应明细的一列。说明、分组等展示组件不存业务值；该类组件的服务端页面接入仍在后续范围。

页面新增字段先保存在该页面的待发布变更中，不立即进入已发布数据模型。保存草稿保留这些变更；撤销或移除尚未发布的新控件时，同时取消不再使用的新字段。发布时检查页面版本与数据模型基线，将数据字段、控件绑定及发布版本放在同一事务中。模型已由其他人修改时保留草稿并提示合并，不能覆盖他人的修改。

从空白表单开始时，页面保存创建时的数据结构基线。数据管理或另一页面先发布后，这份初始页面仍可打开、继续编辑并保存；发布前通过“数据字段”明确采用已发布版本，保留自己的新增字段和布局。独立数据草稿不能被误当作正式模型采用。该顺序及归档、重启和故障回滚已验证，见 page-draft-qa.md。

新字段的归属由落点确定：主区域属于页面的主数据对象，明细区域属于对应明细结构，关联区域必须明确关联对象与修改权限。发布的新字段可供同一对象的其他页面选择，但不自动向其他页面插入控件。同一范围出现同名字段时提示复用或更名，不按名称自动认定为同一字段。

数据管理另列“页面待发布字段”，按来源页面展示已保存的新增主字段和明细列，并可直接定位到页面中的字段。列表与正式字段分开，不展示未保存的浏览器输入。多个页面的同名新增、数据版本变化及独立模型草稿会给出处理提示，不按名称自动合并；取消或发布后刷新列表即可看到变化。

当前实现按数据名称和所属明细检查同名冲突，不把另一页的显示别名当作数据名称。已有字段尚未放入本页时，可检查绑定清单后复用，保留本页标签、提示、宽度和填写设置，采用原数据约束；已有控件已在画布时提供定位入口，不自动丢弃任何新增输入。整段明细复用列出同名同类型列的绑定及仍需新增的列，类型不兼容或重复控件会阻止替换。整个替换支持撤销/重做。

点击发布先保存当前草稿，再检查服务端使用情况；关闭检查窗口不会发布。确认提交携带预览标识，服务端在发布事务中重新计算。页面、模型或预览中列出的使用情况已变化时，保留草稿并要求重新检查。该检查覆盖新服务端入口，尚不包含旧本地编辑器的条件计算和外部配置。

选择已有数据时，编辑器提供可搜索的已有字段。拖入已有字段只增加页面控件，不复制数据。具备模型编辑权限的人仍可添加新字段，发布前显示新增字段及影响范围；只有页面编辑权限的人可以复用已有字段、调整布局和增加展示组件。

控件面板区分已有字段、新建字段和布局展示组件。分组、说明和分隔线不创建数据字段。字段已有绑定时，复制控件默认继续绑定原字段；只有明确选择新建字段才创建另一份业务值。

稳定字段指身份稳定。调整显示名称、顺序、宽度不改变字段 ID；修改业务类型或约束属于数据模型变更，需要校验已有数据与使用方。不能通过重命名或拖拽位置制造一个同名但不同身份的字段。

## 设计草稿与记录草稿

表单设计时拖入新字段形成页面草稿中的待发布新增；发布时才将字段与页面控件一起生效。用户填写已发布页面时保存的记录草稿，只保存这一条业务记录的值，不增加字段、不发布模型或页面。两种草稿在不同任务入口处理。

2026-10-09 05:26：新服务端已支持记录草稿保存、刷新续填及原子提交，见 record-drafts-qa.md。草稿允许暂缺必填项，仍遵守值类型与当前权限；正式提交按原数据版本与明确页面版本校验。草稿不参与关联和流程，提交保留原记录和明细身份。旧记录状态与轨迹的迁移转换仍待接入。

## 一份数据的多个页面

以通用的交付明细为例，数据对象包含计划数量、实收数量、检验结论三个字段。

| 页面 | 展示字段 | 处理方式示例 |
| --- | --- | --- |
| 登记页 | 计划数量 | 登记人员创建记录 |
| 接收页 | 计划数量、实收数量 | 接收人员查看计划并填写实收 |
| 检验页 | 实收数量、检验结论 | 检验人员查看实收并填写结论 |

三页绑定同一条记录及同一明细行。页面不复制数量，不依赖数据触发器同步。流程任务指定需要处理的记录或行，再选择适合该任务的页面。

页面默认只读或隐藏属于交互设置，服务端授权决定实际可读写内容。页面设置只能收紧体验，不能扩大用户权限。查询、候选项、导出和绕过页面的请求仍遵循服务端授权。

同一业务中的不同对象仍保持独立，例如交付单关联多张检验记录。组合页面通过明确关系和记录选择展示它们，不把多张记录无条件合并写回。每个可编辑区域必须能确定记录、字段及必要的明细行身份。

## 修改和删除

| 操作 | 结果与校验 |
| --- | --- |
| 从页面移除控件 | 只移除页面引用，数据字段与已有值保留 |
| 更改页面标签和布局 | 仅修改该页面，不改变其他页面的命名和排列 |
| 更改数据字段名称 | 保留字段 ID；显示各页面是否采用默认名称或自己的标签 |
| 删除或停用数据字段 | 在数据管理中检查页面、关系、计算、权限和流程依赖，明确历史处理；有有效依赖时阻止破坏性删除 |
| 更改字段类型或强约束 | 检查兼容性与已有记录，不能静默重解释历史数据 |
| 删除页面 | 检查流程和导航使用情况；不同时删除数据对象和记录 |

数据管理允许保存尚未解决引用的模型草稿；发布时检查当前页面和关系依赖，阻止移除仍在使用的字段。预览逐项列出主字段和明细列规则差异，统计本次新规则下不符合要求的使用中记录，但不迁移或返回业务值。确认发布会重新核对预览，使用情况改变时保留草稿并要求重新检查。

已保存的数据草稿可以明确放弃，恢复最近已发布的名称与结构；其他页面草稿、发布历史和业务记录保留。没有发布过的对象不提供恢复发布版本。页面草稿也可按版本检查放弃，恢复本页最近发布的名称、控件和绑定，同时取消尚未发布的新字段；不回退共享数据对象、其他页面或已有记录。成功后清空当前编辑器的撤销历史，失败则保留输入。尚未发布过的页面没有可恢复基线；页面归档及恢复已验证，详见 page-lifecycle-qa.md；归档保留草稿、字段和记录，阻止普通入口及新流程使用，已发任务按原版本继续。恢复前列出模型变化，不自动采用新版。

数据校验与页面校验分开：业务数据的永久约束属于数据对象；某次提交或某个节点的补全要求属于页面或任务，不能因为另一部门稍后才填写的字段缺失，就阻断前一阶段建立记录。

## 版本和兼容

数据对象版本与页面版本分别发布。页面版本绑定明确的数据对象版本或经验证兼容的字段集合；流程发布引用页面及数据契约版本。历史任务保留其处理依据。不能把已发布页面直接改成读取未验证的新字段含义。

已有页面通过“数据字段”查看新增字段和约束差异，再采用新的已发布模型；当前布局、别名与未发布新增字段保留，采用新版本不会自动插入控件。历史记录不会因为页面增加字段而自动迁移。当前实现由管理员预览新增字段及默认值后明确升级记录，只允许已有字段语义不变的兼容新增；类型、约束或归属变更以及无法补全的必填字段会阻止升级。升级保留原值和明细行身份，并记录审计。旧页面仍可访问兼容升级后记录中的原字段。

迁移保留现有字段 ID 和明细行 ID。旧表单首先转换成一个数据对象与一个默认页面，记录保持原对象对应关系。客户端临时兼容适配器可以恢复原 FormSchema 供旧页面运行，但不能将适配器输出当作已经完成服务端分离。

## 实现顺序与验收

1. 定义独立数据对象、页面控件绑定与版本契约；建立旧 Schema 的转换和兼容测试，保留全部旧配置。
2. 服务端迁移和读写支持独立契约，验证布局更新不会发布新的数据版本，模型变更会检查页面和流程依赖。
3. 接入应用层数据管理和页面资源入口，保留新建表单的默认短路径；新增字段与页面绑定原子保存。
4. 同一数据创建两个页面，改变一页布局或移除控件后，另一页及记录不受影响。修改同一业务值时两个页面读取一致结果。
5. 流程从不同节点打开不同页面，记录与行绑定不改变；服务端拒绝页面未授予、字段无权限和非法版本绑定的修改。

第一步契约和转换完成后才继续固化关系配置与任务页面入口。现有关系服务、并发保护和明细身份可以复用；不能用增加一个数据管理菜单来代替上述验收。
